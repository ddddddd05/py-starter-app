# 开发记录：从“课程列表”到“像素闯关”

这个项目用 Claude Code 辅助开发（vibe coding）。AI 负责写代码；我负责定需求和玩法、做取舍、在模拟器上实际玩、发现问题后让它改，并决定什么时候算“做完”。下面记录 v1.1（闯关版）这一轮里实际做过的决策和踩过的坑。

## 1. 需求：为什么要改成闯关

v1.0 的首页是一个普通列表，12 关都能直接点开，答题就是“选一个、提交、看对错”。自己用下来的感受是：**功能都有，但不像会想每天打开的东西**。

目标定成：界面像小游戏，有闯关、解锁、奖励，但**不能牺牲学习效果**。

## 2. 玩法上的几次取舍

| 问题 | 最初的想法 | 最后的决定 | 原因 |
|---|---|---|---|
| 学和练的顺序 | 进关直接打怪 | **先学习、再挑战**，学习阶段不扣血 | 零基础的人还没学会就被扣血，很容易放弃 |
| 答错扣完 3 颗心 | 只影响星级 / 失败重来 | **失败重来**，但写代码可以随便“试运行”，只有“出招”错了才扣血 | 保留游戏紧张感，又不惩罚试错 |
| 看提示 | 扣血 | **不扣血，只影响星级**；翻笔记最多 2 星 | 鼓励学扎实，但不会卡死 |
| 游戏怎么和知识结合 | 一步到位做“融入式”（代码直接控制游戏） | **分两步**：先做完整的外包装式闯关，判题结果里预留 `events` 字段，以后挑第 6/7/11 关升级成融入式 | 一次重做 12 关的场景和动画风险太大；预留接口避免以后推翻重写 |
| 报错呈现 | 换成纯游戏台词（“蓄力符没发出来”） | **游戏台词 + 原来带行号的大白话报错** | 只有台词的话学不到“少了冒号”这个真正的知识点 |
| 错题 | 错题本 | 错题带错因标签变成**复仇怪**，在后面的关卡回来 | 把错题本变成间隔复习，正反馈更强 |
| 美术 | 网上找像素素材 | 角色和怪物**用字符画在代码里绘制** | 没有版权问题，换色就能做出不同章节的怪 |

## 3. 实现

- **Python 层**（`game.py`）：章节、学习卡片（按句号把讲解拆成小卡片）、每关 1 道小练习、怪物、错因标签和 NPC 台词。题目、判题、AI 老师都没动，游戏层只是换一种呈现。
- **判题结果加字段**：`events`（驱动动画）、`tag`（错因）、`npc`（台词），原来的 `feedback` 保持不变，旧页面不受影响。
- **存档**（`GameStore`）：解锁、星级、经验、徽章、复仇怪用 SharedPreferences 存，**没有改 Room 数据库结构**，避免写迁移、丢用户的做题记录。
- **防刷**：重复挑战时，过关奖励只给第一次，星级奖励只给新增的星。

## 4. 测试中发现并修掉的问题

每一项都是在模拟器上实际玩出来的：

| 现象 | 原因 | 修法 |
|---|---|---|
| 第 5 关示例运行后出现莫名其妙的“小明” | `input()` 需要输入，学习页没地方输入，代码里写死了“小明” | 代码用到 `input()` 时自动出现输入框，写什么程序就用什么；输入框空着就先提醒 |
| 换到下一场战斗，提示按钮还显示“再给点提示” | 换战斗时没重置按钮文字 | 每场战斗开始时重置 |
| 战斗里提示“点‘问老师’”，按钮却叫“问小精灵” | 判题反馈是旧页面的文案 | 改成通用的“看看提示” |
| 统计面板本该换行的地方挤成一行 | 字符串里写的是真正的换行符，安卓会当成空格 | 改成 `\n` 转义 |
| 没解锁的关卡星星也是亮黄色 | — | 未解锁时星星改成灰色 |
| 选择题答对后看不出选的是哪个 | — | 答对的选项标成绿色 |
| 命令行打包报 `Unable to establish loopback connection` | Windows 用户名是中文，Java 临时目录路径含中文 | 把临时目录指到纯英文路径（写进了 README） |
| 新装的版本“消失”，模拟器里又是旧版 | 启动模拟器时用了不保存快照的参数，重启后回到旧快照 | 重新安装，正常方式启动模拟器 |

## 5. 验证

- Python 测试从 69 个增加到 **117 个**。12 道新的小练习，每道都**真的运行代码**核对正确选项；错因标签用真实的错误代码测试（少冒号、少引号、死循环、输出不对……）。
- **可复现性**：只拷贝仓库里的文件到新文件夹，在全新的 Python 环境里跑测试、从零 `assembleDebug`，都通过。
- **模拟器实测**：学习 → 小练习答错 → 三场战斗 → 答错扣心 → 挑战失败 → 再挑战 → 通关拿星 → 徽章 → 解锁下一关 → 复仇怪出现并被征服 → 升级，完整走通，并录了屏（`docs/demo.mp4`）。

## 6. 下一步

- 挑第 6 关（if 走岔路）、第 7 关（for 一次打 5 只史莱姆）、第 11 关（def 自创技能）升级成“融入式”玩法，用 `events` 驱动专属动画；
- 单步慢放执行：高亮当前行，同步显示变量变化；
- MP（简洁度）奖励：代码越简洁星越多，自然引出循环和函数。

# v1.2：补齐竞争力短板

复盘 v1.1 时列出了几个面试官一眼就会注意到的问题，这一轮一项一项补：

| 短板 | 做法 |
|---|---|
| 技术栈老：全是 Java + 传统 View | 新功能用 **Kotlin + Jetpack Compose** 写，和原有 Java 页面在同一个项目里混合共存 |
| 一个真实 bug：挑战中旋转手机，战斗从第 1 战重来、心回满（还能被用来“回血”） | 战斗状态移进 **ViewModel**，页面重建后按状态恢复；在模拟器上横竖屏来回切验证 |
| 安卓端没有测试 | 把星级、结算防刷、解锁、徽章规则抽成**纯函数**，写 20 个 JUnit 测试；写 Espresso UI 测试走主流程 |
| 没有 CI | GitHub Actions：Python 测试、单元测试 + 打包、模拟器 UI 测试三个任务 |
| 安装包 42 MB | R8 压缩 + 按 CPU 架构拆分，真机包约 25 MB；签名密钥从本地文件 / 环境变量读取，不进仓库 |

## 新功能

- **单步慢放（可视化调试器）**：Python 端用 `sys.settrace` 逐行记录行号、变量、输出和循环轮次（`tracer.py`），安卓端用 Compose 回放：当前行高亮、变量背包里刚变化的变量变黄。解决的是零基础最大的困惑——“代码是怎么一行行跑的”。
- **融入式玩法**：v1.1 预留的 `events` 接口在这里用上了。答对写代码题后，用单步跟踪器把代码真实执行一遍，按执行过程生成专属动画：循环跑几轮就连击几刀；判断显示实际走了哪条路和条件；自己 `def` 的函数变成技能。游戏机制本身就是知识点，而不是答题外面包一层皮。
- **MP 简洁度**：和参考写法比较有效行数。只加经验、不影响星级——对零基础来说“先写对”比“写得短”重要，不应该因此被惩罚。

## 这一轮踩到的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| UI 测试一启动就报 `NoSuchMethodException: InputManager.getInstance` | Espresso 3.6 调用的系统方法在新版安卓里被删了 | 升级到 Espresso 3.7 |
| UI 测试点选项时报“匹配到 2 个控件” | 选项文字和题目代码块的文字一样 | 匹配条件加上“可点击” |
| 跑完 UI 测试，模拟器上的进度全没了 | 测试开始前会清空进度，结束后 Gradle 还会卸载 App | 跑之前用 `run-as` 把存档和数据库备份出来，测完装回去恢复；README 里写了提醒 |
| 电脑上跑 JUnit 时 `Store` 类加载就报错 | 静态字段里创建了安卓的 `Handler`，电脑上的安卓 API 只是空壳 | `unitTests.returnDefaultValues = true` |
| 连击的飘字出现在标题栏上 | 用的是相对直接父布局的坐标，没换算到整个页面 | 改用窗口坐标换算 |
| 拆分安装包后调试版文件名变了，CI 找不到 `app-debug.apk` | 拆分对所有构建类型生效 | 只在打正式版时拆分 |

## 验证

- Python 157 个测试、JUnit 20 个、Espresso 2 个，全部通过；
- 模拟器实测：慢放逐行回放、横竖屏切换不丢进度、第 6 关岔路口、第 7 关 5 连击、MP 加成、复仇怪；
- 正式版（R8 压缩后）装到模拟器上，地图、运行代码、单步慢放都正常，没有崩溃。
